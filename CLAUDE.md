# Workout Log (personal iPhone workout app)

Single-file vanilla JS/HTML app (`index.html`, ~3,500 lines). Hosted on GitHub Pages; the filename must stay lowercase `index.html`. No build step, no backend, works offline.

## Data
- All data is in localStorage under `workoutLogDB_v1`: `{workouts:[], exercises:[]}`.
- Exercise definitions hold cues, links and notes, shared across workouts.
- Workouts hold `warmup` and `main` arrays of exercise instances. Each instance has `secondaryType` (weight, band or time) and `sets:[{reps, weight, band, time, done, warm}]`.
- `done:false` = unchecked. A missing `done` is old data and counts as checked. `warm:true` marks a W (warmup) set.
- Counted sets (`isCounted`) are checked, non-W sets. They feed progress deltas, PRs, history and stats.
- Never change the storage key or data shape without a migration. This is real training history.
- Exercise icons are looked up by lowercase exercise name (`EXERCISE_ICONS`). Renaming an exercise means renaming its icon key too.
- Search tags live in code (`EXERCISE_TAGS`, also keyed by lowercase name), not in saved data. The add-exercise and circuit-timer searches update on every keystroke and match each term against the start of any word in the name or any tag (`searchWords`/`exerciseMatchesTerms`: "sh" finds Shoulder, not pushdown); tag-only matches list after name matches and show the matched tag. Tags leave out words already in the name. Renaming an exercise means renaming its tag key too.
- Add-exercise search chips (`renderSearchChips`): with an empty box, the section's 10 most common tags (browse); while typing, up to 8 whole words from names and tags that start with the word being typed, each with its match count. Tapping a chip fills it in.
- Before you type a search, the warm-up section's add-exercise list shows only exercises tagged `warmup` or `mobility` (`isWarmupExercise`), and the main section's list shows only the rest. Searching reaches across both sections only by exercise name; matches that rely on a tag only show if the exercise belongs to the section being added to (`pickerSearchMatch`). Chip counts follow the same rule. A Circuit workout's "+ Add exercise to circuit" opens the same add-exercise sheet (`openPicker('circuit')`), treated as the main section; `addInstanceToWorkout` puts the exercise id in `w.circuit.exercises`. Untagged (user-created) exercises count as main. An exercise tagged `main` as well as `warmup`/`mobility` shows in both lists (`showsInPickerList`).

## Look
- Theme: Midnight (dark, lime accent, coral PRs, yellow warm-up) is on via `class="theme-midnight"` on `<html>`. Its rules are all prefixed `.theme-midnight` at the end of the stylesheet. Removing the class falls back to Sage & Ember (sage/amber), whose rules are kept unprefixed.
- Exercise drawings are two-tone: elements of the person have `class="fig"` (lime in Midnight), equipment, walls and floor have `class="eq"` (grey). New drawings need these classes on every path/circle.
- Exercise cards with no checked sets (`.not-started`; a set counts if `done !== false`, W sets included) have a grey accent bar and no fill; once any set is checked (`.started`) the bar is warm-up yellow or workout lime as before.
- Exercise cards: drawing tile 47px (4px padding, 13px radius), head padding 16px, 12px between cards, names 15.5px. Add-exercise search list: bare drawings 34px, rows 13px vertical padding.
- Home-screen icon: `apple-touch-icon.png` (180x180, a dumbbell with one lime plate each side on the Midnight background) and `favicon-32.png` sit next to `index.html`. iOS caches the icon when a bookmark is added, so re-add the bookmark to see a new icon.

## Behavior that must be preserved
- Dates use the local date (`localDateStr()`), never `toISOString()` (a UTC bug bit once).
- Opening a workout (from the list, a copy, or after the app restarts) shows every exercise card collapsed (`showWorkout`, `shownWorkoutId`); re-showing the same workout keeps its cards as they are. Only one card is expanded at a time: opening a card (or starting to log on one, or adding one) collapses the rest; tapping the open card collapses it. Collapsed state is in memory only.
- When an exercise gets its first checked set (`toggleSetDone`), it moves up within its section to just above the first not-started exercise (`moveUpIfNewlyStarted`); it never moves down, and unchecking leaves it in place. This changes the saved order, same as drag-to-reorder.
- Long-press drag-to-reorder of collapsed exercise cards: those cards (`.reorderable`), every `.exercise-head` and the whole page during a drag (`html.dragging`) have text selection and the iOS callout turned off, so a long-press drags instead of selecting text.
- Wheel pickers only save on real touch input. This fixes an iOS bug where backgrounding the app zeroed values. Do not remove that guard. While a finger is on a wheel (`touching`) nothing is saved or snapped, so long drags with pauses keep scrolling; the value settles after touchend and momentum.
- Copying a workout or adding an exercise gives blank, unchecked sets, with last session's numbers shown beside the exercise. Intentional.
- PRs: weight, set volume, Epley est. 1RM, reps at a weight. A first-ever log is not a PR.
- Circuit timer (4x4 and others) lives in the Workout (main) section of Circuit workouts (type "Circuit", formerly "Cardio 4x4") (`renderCircuitPanel`): rounds/work/rest steppers, the circuit exercise list and a Start button; the warm-up section is unchanged. Each such workout may hold an optional `circuit: {rounds, workSeconds, restSeconds, exercises:[exerciseId]}`, created only on first change, copied with the workout, and repointed/kept by exercise merges and removals. The timer uses Web Audio, wall-clock timing and a wake lock.
- iOS Safari: while the keyboard is up, sheets fit the visible area above it (`syncVisualViewport` sets `kb-open` and `--vv-h`/`--vv-top` on `<html>`), so search results aren't hidden behind the keyboard; a new search scrolls the list to the top. The landing screen shows a small `build-label`; bump it with user-visible fixes so the user can tell whether their phone has the latest page (GitHub Pages can serve a cached copy for ~10 minutes). 16px inputs to avoid zoom, no native confirm() (use in-app sheets), sheets sit above the timer overlays (z-index).

## Testing
Syntax-check the script block with node, then test in Playwright with a mobile viewport and touch events.

## Backlog ideas

- Voice commands (on hold, Nov 2026): the goal is one quick gesture that opens the mic, e.g. "add bench press", "reps 8", "weight 135". Spoken confirmations via `speechSynthesis` would work today.

## Working style
Commit in small steps with clear messages and say what changed. Ask before anything that could alter saved data.
